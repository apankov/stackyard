# ingester — конвейер знаний

Транскрипты встреч (Fathom, Google Drive, ручные) превращаются в задачи
и знания в Obsidian. Состояние — в общем postgres, файлы — в `Ingester_Data_Dir`.

Приложение: `Ingester_Host_Home_Dir` (чекаут репозитория `ingester`).
Архитектура и решения — `docs/` того репозитория, начиная с
`docs/architecture/decisions/0001-razvyortyvanie-na-servere.md`.

Наружу стек не слушает: ни порта, ни vhost'а, ни домена.

## Здесь он работает сборщиком

Принимает сырьё, нормализует, склеивает дубли и атрибутирует по правилам —
и на этом останавливается. Извлечение и всё, что за ним, ждёт в очереди.

Причина арифметическая. Вызов модели — отдельный процесс, и его пик
складывается с памятью воркера. Измерено на нагрузке 85 КБ, по три прогона:

| | |
|---|---|
| `claude -p` | ~245 МБ (от размера входа почти не зависит) |
| `codex exec` | ~100 МБ |
| воркер | ~80 МБ |

Свободно на этой машине около двухсот. Спавн на 245 МБ унёс бы не нас,
а случайного соседа.

**Что из этого следует.** В волте пока ничего не появляется: знания и задачи
рождаются на извлечении. Это склад сырья, а не рабочий список. Смысл держать
его здесь в том, что транскрипты у источников хранятся не вечно, и собирать
их дешевле начать сразу.

Ничего не теряется: сырьё неизменяемо, очередь растёт, и первый же воркер
на машине посвободнее её разбирает — хоть из этой же базы.

## Установка

```bash
# 1. Чекаут приложения
git clone <repo> ~/dev/ingester

# 2. Каталоги данных — руками и заранее.
#    Отсутствующий host-путь bind-mount'а docker заводит САМ И ОТ ROOT,
#    и тогда контейнер под Ingester_Run_As в них не запишет.
sudo mkdir -p /mnt/data/ingester/{raw,machine,inbox,derived,codex}
sudo chown -R "$(id -u):$(id -g)" /mnt/data/ingester
~/dev/ingester/scripts/bootstrap-vaults.sh \
  /mnt/data/ingester/raw /mnt/data/ingester/machine

# 3. Настройки стека
#    Конфиг приложения копировать не надо: config/ingester.yaml лежит
#    в репозитории, секретов в нём нет, машинно-зависимое приходит переменными.
cp stacks/ingester/.env.example stacks/ingester/.env
chmod 600 stacks/ingester/.env
$EDITOR stacks/ingester/.env     # Ingester_Run_As = id -u:id -g, пароль базы,
                                 # ключи Fathom — ДО включения стека

# 4. Проверка раскладки и включение
./scripts/selftest.sh
./docker-compose.sh --all-stacks config -q
./scripts/stack.sh enable ingester
sudo ./scripts/systemd.sh
```

Базу и пользователя заводит `db-initializer` из `stacks/pg/db-init/databases.yaml`,
который генерируется из `Postgres_*` в `stack.conf`. Руками его не правим:
`./scripts/stack.sh --check` ловит расхождение.

Миграции применяет сам воркер при старте — отдельного шага нет.

## Проверить

```bash
./scripts/stack.sh --check
stacks/ingester/scripts/check-health.sh          # то же, что гоняет таймер
docker exec ingester node src/cli/doctor.js      # что настроено, а что нет
docker exec ingester node src/cli/health.js      # работает ли на самом деле
docker exec ingester node src/cli/status.js      # картина целиком, с выводами
docker exec ingester node src/cli/jobs.js dead   # что упало и почему
docker logs --tail 50 ingester
```

`check-health.sh` смотрит на следы работы, а не на живость контейнера:
конвейер, переставший разбирать встречи, снаружи неотличим от конвейера,
которому нечего разбирать.

## Мост с маком

Машинный волт — git-репозиторий в `${Ingester_Data_Dir}/machine`. Мак клонирует
его по SSH, коммитит правки Обсидиана в ветку `mac` и пушит; конвейер разбирает
ветку и отмечает в `.sync/absorbed`, до какого коммита дошёл.

Ветка `main` здесь выгружена в рабочее дерево, поэтому git сам отвергает push
в неё — правило «один владелец у куска текста» держится не на дисциплине.

Агент для мака и порядок его установки — `deploy/mac/` в репозитории приложения.

## Снять режим сборщика

На машине, где хватает памяти на вызов модели:

1. в `stacks/ingester/.env` убрать `Ingester_Models_Enabled=false`
   и `Ingester_Deferred_Kinds`;
2. положить `Ingester_Claude_Code_OAuth_Token` — в контейнере связки ключей
   macOS нет, нужен долгоживущий токен (`claude setup-token` на маке);
3. в `compose.yaml` поднять `mem_limit`/`memswap_limit` до `512m`
   и `NODE_OPTIONS` до `--max-old-space-size=384`;
4. `./docker-compose.sh up -d ingester`.

Отложенные работы разберутся сами: они всё это время лежали в очереди.

## Что пойдёт не так

**`P1000 / password authentication failed` при живой базе.** Разъехались пароли:
`db-initializer` идемпотентен только по факту существования и пароль
существующему пользователю не обновляет. Лечится сбросом пароля в postgres
руками либо удалением пользователя и повторным прогоном инициализатора.

**Контейнер не пишет в волты.** `Ingester_Run_As` не совпал с владельцем
`Ingester_Data_Dir`, либо каталоги завёл docker от root — см. шаг 2.

**Мак пушит, а ничего не происходит.** `docker logs ingester | grep sync`.
Проверьте, что `SYNC_ENABLED=true` и что мак пушит именно в ветку `mac`.

**Очередь растёт и не разбирается.** В режиме сборщика это норма,
`check-health.sh` покажет, сколько работ ждёт.

**Извлечение молча не работает в полном режиме.** Почти всегда токен:
в контейнере связки ключей нет, `health.js` это различает.

## Бэкап

`Backup_Files` в `stack.conf` указывает на `Ingester_Data_Dir` целиком.
База в него не входит намеренно: она производная и пересобирается из файлов,
а файлы — нет. Путь обязан существовать до включения стека, иначе `backup.sh`
падает, и падает не только за нас.
